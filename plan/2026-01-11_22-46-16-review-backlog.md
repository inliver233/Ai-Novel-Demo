## Review dimensions（用于拆解 issue）
- 安全：鉴权/RBAC/IDOR；输入校验；SQL/模板注入；CSRF/会话/CORS；密钥/隐私/日志脱敏
- 数据层：SQLite 单 worker；LLM 调用不持有长事务；迁移/基线一致；幂等/回滚/一致性
- 质量：错误处理；可观测（request_id/结构化日志）；E2E 稳定性；命名清理（外部项目残留）
- 模块逐项：WorldBook / Analysis+Annotations / Auth+RBAC / Vector / Structured+Update / Graph / Fractal / Style+PostEdit

## Execution strategy（后续执行时必须遵守）
- 每条 `issues/2026-01-11_22-46-16-review-backlog.csv` 的 issue：
  - 先把该行 `Dev_Status=DOING`（保存 CSV）→ 再改代码/文档/测试 → 运行 `Test_Method` → 更新 `Review1_Status`/`Dev_Status` → commit（含 CSV）→ push
  - review 结论必须落盘到 `docs/reviews/<ID>.md`（作为证据与可追溯输出）
- 批次回归：所有行 `Dev_Status=DONE` 后再统一跑 `pwsh test/run-all.ps1` 并一次性更新 `Regression_Status=DONE`（meta commit 仅改 CSV）
