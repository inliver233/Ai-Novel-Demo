# 搜索 IA 决策 v2：替代旧「术语表/术语映射」

## 背景

历史上「术语表/术语映射（Glossary）」页面承担了两类需求：

1. 维护“术语 → 别名”映射（用于可选的查询增强）
2. 作为“全项目检索入口”的替代品（但与世界书/图谱/记忆等功能存在边界与冲突）

在 `完整任务要求.txt` 中明确提出：**应将“术语表”重构为一个强大的全局搜索引擎**（类似 VSCode 全项目搜索），覆盖章节/大纲/世界书/角色/记忆/表格/图谱等多来源，并支持模糊搜索与跳转。

## 决策（Decision）

- **保留 `SearchPage` 作为唯一的“全项目搜索引擎”入口**：路由为 `/projects/:projectId/search`，命名为「搜索引擎」。
- **旧 `GlossaryPage` 不再作为用户入口**：`/projects/:projectId/glossary` 作为兼容入口保留，但**重定向到** `/search`（避免出现两套“搜索”入口造成困惑）。

## 命名与导航（Routing & Naming）

- 导航/标题统一使用「搜索引擎」指代全项目检索能力。
- 避免在路由/标题层面出现 `/search` 与 `/glossary` 的重复命名（用户只需记住一个入口）。

## 兼容性与边界

- 不删除后端 Glossary 能力：如未来仍需“别名/术语增强”，可将其作为**高级/可选**配置能力，而不是与全局搜索入口混用。
- UI 层面以“全局搜索”为主线，Glossary 相关能力如需保留，应以“配置/增强”形态出现，而不是单独的主入口页面。

## 后续工作（映射到 Issue）

- MVP-041：扩展 `search_index` 覆盖更多来源类型（保证“搜得到”）。
- MVP-042：搜索页面增强：模糊搜索与多来源结果呈现（保证“好用/能跳转”）。
